### Q-CV-001 · scope · Medium · [Pattern]

### Q-CV-002 · depth · Hard · [Pattern]

You list Docker and CI/CD. What actually happens when you push to main?

<details>
<summary>Answer</summary>

**Short answer (say this):** "GitHub Actions checks out, installs dependencies, and runs `makemigrations --check --dry-run` — that fails the build if anyone changed a model without generating the migration. Then it builds the Docker image and pushes it tagged with both the commit SHA and latest, pulls that image back and runs the test suite *inside the container*, so tests run against the real artefact rather than a fresh environment. Deployment SSHes into the VPS, pulls the SHA-tagged image with a retry loop for registry propagation, and brings the compose stack up on the new tag."

**Source:** `PROFILE.md` §12. This is a strong answer — the migration-drift gate and the test-inside-the-image detail are both unusual for a trainee applicant.
</details>

### Q-ASK-006 · closing · [Generic]

"Is there anything about my background that gives you doubt? I'd rather answer it now than leave it unaddressed."

<details>
<summary>Why this one</summary>

**The strongest closing question there is.** It surfaces the objection while you can still answer it — and with your profile, there almost certainly *is* one: overqualified for a trainee req, or a flight risk. Better to hear it and respond than to be rejected for something unsaid.

Ask it calmly, then stay quiet and let them answer.
</details>
